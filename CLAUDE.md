## What this project is

A PWA for checking the current closure status of the Mt. Rainier pool. It scrapes `mtrainierpool.com`, stores closure messages in Supabase, and runs them through a Supabase AI model (`pool-operator`) to extract structured closure/reopening dates.

## Monorepo layout

Two separate runtime stacks share this repo:

- **`frontend/`** — React + Vite PWA (Yarn workspace, Node/browser target)
- **`supabase/functions/api/`** — Hono Edge Function (Deno, runs on Supabase)
- **`scripts/`** — Deno CLI for triggering the edge function and generating the API client

The root `deno.json` manages Deno workspaces (`supabase/functions/api` and `scripts`). The root `package.json` manages the Yarn workspace (`frontend/`).

## Commands

### Frontend (run from repo root or `frontend/`)
```sh
yarn workspace frontend dev        # dev server on :3000
yarn workspace frontend build
yarn workspace frontend typecheck  # deno check
yarn workspace frontend lint       # deno lint
```

### Backend / Supabase
```sh
supabase start                     # start local Supabase stack
supabase stop
supabase functions serve           # serve edge functions locally
yarn gen:types                     # regenerate DB types from local Supabase
yarn gen:schema                    # dump schema SQL
yarn gen:seed                      # dump seed SQL (public + vault)
yarn gen:seed:public               # dump public schema seed only
yarn gen:seed:vault                # dump vault schema seed only
```

### Scripts (Deno CLI)
```sh
yarn pool check                    # call /api/check against SUPABASE_URL + keys
yarn pool create-client            # regenerate scripts/client/ from OpenAPI spec
yarn lint                          # deno lint (root + supabase + scripts)
yarn typecheck                     # deno check
yarn deno:refresh                  # bust Deno module cache
```

`yarn pool check` requires `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` in the environment (load via `.env` — `@std/dotenv/load` is imported automatically).

## Architecture

### Edge Function (`supabase/functions/api/`)

Hono app with `@hono/zod-openapi`. The single route is `GET /api/check`:

1. Fetches `https://mtrainierpool.com` and extracts `#updates_banner p` text.
2. UUIDs the banner text (UUID v5 under a custom namespace) to deduplicate — upserts into `pool_updates`.
3. Fires `EdgeRuntime.waitUntil(runPoolOperator(...))` to call the `pool-operator` Supabase AI model, which returns structured JSON with `closure_date`, `reopening_date`, `confidence_score`, `reasoning`, and `flags`. Upserts into `pool_closure_analysis` on conflict of `pool_update_id`.

A `pg_cron` job (`pool-check-daily-6am-pst`) calls this endpoint daily at 6:00 AM PST (14:00 UTC) using credentials stored in Supabase Vault.

The edge function uses `@supabase/server` middleware (`withSupabase({ auth: ["secret"] })`) — callers must pass the service role key.

### Generated API client (`scripts/client/`)

Auto-generated by `@hey-api/openapi-ts` from the live OpenAPI document exported by the Hono app. **Do not hand-edit files in `scripts/client/`** — regenerate with `yarn pool create-client`.

### Frontend

- **UI**: Mantine v9 (dark scheme default), `@tanstack/react-router`, `@tanstack/react-query`
- **Auth**: `SupabaseProvider` in `frontend/src/api/supabase.tsx` wraps the whole app; exposes `useAuth()`. The router context carries `auth` and `queryClient`.
- **Route tree**: Generated by the TanStack Router Vite plugin — **do not edit `src/routeTree.gen.ts` manually**. Add routes as files under `src/routes/`.
- **Auth-gated routes**: Files prefixed `_auth` (e.g., `_auth.home.tsx`) live under the `_auth` layout route, which redirects unauthenticated users to `/login`.
- **Data fetching**: `queryOptions` objects in `src/api/` are passed to `useQuery`. Stale time is 1 hour for pool data.

### Database schema (public)

- `pool_updates` — raw scrape results: `id` (UUID v5), `message`, `source`, timestamps
- `pool_closure_analysis` — LLM output linked 1:1 to a pool update via `pool_update_id`: `closure_date`, `reopening_date`, `confidence_score`, `reasoning`, `flags[]`

RLS is auto-enabled on all `public` tables via an event trigger (`rls_auto_enable`).
